# dollarization-pipeline

[한국어 버전](README.md) · See [OPERATIONS.en.md](OPERATIONS.en.md) for a how-to-run guide

An ETL pipeline that automatically collects foreign-currency-deposit (FCD) statistics per country and loads them into Supabase PostgreSQL.

## src/parsers/ — per-country parser structure

`DirectExcelStrategy` and `InteractiveWebStrategy` only handle shallow dispatch based on the data format (how the Excel file is downloaded); the actual per-country parsing logic lives in its own independent file at `src/parsers/{country_code_lowercase}.py`. To implement a new country, just add a single `src/parsers/{cc}.py` file — both Strategy classes dynamically load and run that module via `importlib.import_module(f"src.parsers.{country_code.lower()}")`.

Each parser module must export:

| Name | Description |
| --- | --- |
| `FILE_URL` | The URL of the actual file to download. `None` if it should just use `target['source_url']` as-is |
| `parse(content: bytes, country_code: str) -> pd.DataFrame` | Returns a long-form DataFrame |

### When there's no single file download: `FILE_URL = "__RENDER__"`

When there's no single downloadable file URL — e.g. the page itself is the data source, or you need to walk several yearly archives — export `render(target: dict) -> pd.DataFrame` instead. When `src/collectors/base.collect_via_parser()` sees `FILE_URL == "__RENDER__"`, it skips the download step and calls `module.render(target)` directly. This pattern is used both when the page has to be rendered with Playwright (`can.py`, `slv.py`, `aut.py`) and when multiple files need to be merged into one series (e.g. `abw.py`, which walks the CBA's yearly archives from 2010 to present).

### Standard fallback for failed PDF text extraction: OCR

Some PDFs give `pdfplumber.extract_text()` an empty result or text with scrambled character order (a case found in `abw.py`: some years' CBA monthly bulletins are actually rendered upside-down, so plain text extraction comes out character-reversed — this kind of issue is hard to catch by eye/vision-model inspection of the image; it has to be judged by trying different rotations and checking OCR output quality against the actual pixels).

This project's **standard procedure** is:

1. First try normal parsing with `pdfplumber.extract_text()`.
2. If that fails (no text, or the expected marker/row pattern doesn't appear), call `src/collectors/base.find_page_text_via_ocr(pdf, marker, scorer=...)`.
   - It renders the first several pages as images and runs `pytesseract` OCR at each of 0/90/180/270 degree rotations.
   - Keep `marker` loose (OCR often drops punctuation/digits, so use just the key words — e.g. `"COMPONENTS OF BROAD MONEY"` instead of `"TABLE 2: COMPONENTS OF BROAD MONEY"`).
   - Pass a `scorer(text) -> int` function such as "how many rows does the actual parser regex extract from this text". If you pick the first rotation based on the marker alone, you risk picking a rotation where the title happens to look roughly right but the numeric content is garbled.
3. Feed OCR'd text through the same parsing function as normal text, but first strip OCR-specific noise tokens (e.g. footnote underscores misread as `=`). If a single garbled digit causes a whole row to fail matching, silently skip that month rather than guessing a value — a missing value is safer than a wrong one.

If text extraction breaks for a new country, reuse this pattern rather than writing an ad-hoc workaround on the spot: use `find_page_text_via_ocr`, improving the function itself if needed. The `tesseract-ocr` binary must be installed on the system (`brew install tesseract` / `apt install tesseract-ocr`) — the `pytesseract` package in `requirements.txt` is only the Python bindings and doesn't substitute for the binary.

## targets.json schema

JSON Schema definition: [config/targets.schema.json](config/targets.schema.json)

```json
{
  "country_code": "ISO 3-letter code",
  "data_type": "Direct Excel / PDF Bulletin / Interactive Web / No Standalone Source",
  "source_url": "Final download URL or statistics landing page URL (null if none)",
  "update_frequency": "Monthly / Quarterly / Annual / null",
  "requires_js": true,
  "notes": "Guide to the collection path and other remarks",
  "pending_parsers": [
    {
      "kind": "PDF",
      "source": "Name of an additional publication",
      "status": "todo",
      "notes": "Description of a supplementary source planned for later"
    }
  ],
  "adapter": {
    "implemented": "Whether the actual parsing logic is implemented and produces values (true/false)",
    "strategy_class": "The Strategy class name handling this country (null if none)",
    "status": "success / failed / needs_research / todo",
    "notes": "Reason it's blocked, or which cell/sheet location was used"
  }
}
```

The `adapter` field tracks the implementation status of a country's actual collection code (whether `src/parsers/{country_code}.py` exists). `data_type` is just a classification of the source's format — whether it actually produces values is tracked via `adapter.status`. When the main source works but a parser for a supplementary publication (e.g. a PDF) doesn't exist yet, a `status: "todo"` entry is added under `pending_parsers` (e.g. GIN's quarterly/annual reports).

## Long-form output schema

Every collection strategy (`ScrapingStrategy.collect_and_parse`) returns a pandas DataFrame with these columns.

| Column | Description |
| --- | --- |
| country_code | ISO 3-letter code |
| year | Year |
| period | Period label (e.g. Q1, Annual, 2026-01) |
| indicator | Indicator name: `FCD` / `TD` / `FCD_TD_RATIO` (legacy `foreign_currency_deposits` -> `FCD`) |
| value | The value. **`FCD_TD_RATIO` is a percentage, 0–100** (`(FCD/TD)*100`), not a 0–1 fraction |
| updated_at | Collection timestamp (ISO 8601) |

Upserted into the Supabase `deposit_dollarization` table on the composite PK `(country_code, year, period, indicator)`. Country metadata (`config/targets.json`) is upserted into the `country_metadata` table.

## Supabase integration

### 1) Create tables

Run `sql/deposit_dollarization.sql` + `sql/country_metadata.sql` from the Supabase Dashboard **SQL Editor**, or:

```bash
python main.py --init-db
```

#### `deposit_dollarization`

| Column | Type | Description |
| --- | --- | --- |
| country_code | TEXT | ISO3 (PK) |
| year | INTEGER | Year (PK) |
| period | TEXT | e.g. `YYYY-MM` (PK) |
| indicator | TEXT | `FCD` / `TD` / `FCD_TD_RATIO` (PK) |
| value | DOUBLE PRECISION | The value. **`FCD_TD_RATIO` = (FCD/TD)×100 → a 0–100 percentage** (not 0–1) |

Cleaning up legacy indicator names:

```bash
python main.py --migrate-indicators   # foreign_currency_deposits -> FCD (keeps the existing FCD row on conflict)
```

### 3) Run

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
playwright install chromium   # needed for the Interactive Web strategy

python main.py --init-db
python main.py --dry-run --status success --only-with-parser
python main.py --status success --only-with-parser          # all successful adapters -> Supabase
python main.py --countries UKR,URY,RWA                      # specific countries only
```

| Option | Description |
| --- | --- |
| `--dry-run` | Collect only, don't write to the DB |
| `--countries UKR,URY` | Filter by ISO3 |
| `--status success` | Filter by `adapter.status` |
| `--only-with-parser` | Only countries with an `src/parsers/{cc}.py` module |
| `--init-db` | Create tables/indexes (`deposit_dollarization` + `country_metadata`) |
| `--migrate-indicators` | Bulk-migrate the legacy `foreign_currency_deposits` name to `FCD` |
| `--list-db-stats` | Print per-country row counts in Supabase |
| `--db-summary` | Summarize loaded data (coverage, indicators, thin rows). Save as JSON with `--summary-json PATH` |
| `--upload-targets` | Upsert `targets.json` into `country_metadata` |
| `--thin-threshold N` | Row-count threshold used by `--db-summary` (default 30) |
| `--include-annual-thin` | Include annual/semi_annual in the thin-row list too (excluded by default) |
| `--workers N` | Number of concurrent collection slots (default 4). **Starts the next country as soon as one finishes** |
| `--timeout-sec N` | Hard per-country timeout (kills the process). 0=unlimited |
| `--upsert-batch-size N` | Flush an UPSERT once N countries have succeeded (default 5) |
| `--skip-existing` | Skip a country if it already has at least 1 row in the DB |
| `--skip-if-rows-gte N` | Skip a country if its DB row count is ≥ N |
| `--max-db-rows N` | Only target countries with DB row count ≤ N, or not yet collected (for reworking thin parsers) |
| `--min-db-rows N` | Only target countries with DB row count ≥ N |

```bash
# Recommended: 8 concurrent workers + 120s timeout + upsert every 5 countries + skip already-loaded countries
python main.py --status success --only-with-parser \
  --workers 8 --timeout-sec 120 --upsert-batch-size 5 --skip-existing

# Re-run only thin (<=30 rows) or not-yet-collected countries (for reworking parsers)
python main.py --status success --only-with-parser \
  --workers 6 --timeout-sec 180 --max-db-rows 30

# DB status / summary / metadata upload
python main.py --list-db-stats
python main.py --list-db-stats --max-db-rows 30
python main.py --db-summary
python main.py --db-summary --summary-json runs/db-summary.json
python main.py --upload-targets
```

### Execution model

```
targets queue ──► [collection workers × N] ──(next country as soon as one finishes)──► UPSERT queue
                        │                                                                │
                     timeout                                                             ▼
                   process kill                                                [UPSERT worker] flushes every N countries
```

- Countries are **fully independent** → no batch barrier (the old `--batch-size` structure, which waited for a batch of 10 countries to finish, has been removed).
- With `--timeout-sec`, each country runs in a **child process**; it's `terminate`d/`kill`ed on timeout.

Scheduled quarterly run: monorepo root [`.github/workflows/quarterly_etl.yml`](../.github/workflows/quarterly_etl.yml)
(1st of Jan/Apr/Jul/Oct, UTC). Can also be run manually with a country filter via `workflow_dispatch`.
